## 一、逐问题失败链

### A-1 Dapper Saga 快照静默丢数据（最重的漏检——文件被读过三遍）

**接触史** [实证]：①第五十二轮片3 全文读过 DapperSagaStateStore.cs（三栈 Store 域 61 文件之一）；②同轮我**亲手修改过该文件**（P2-1 AOT 注释同步，review-full.md:35 提交记录在案）；③第五十三轮片C 复核过 :19 注释。缺陷（`SerializeState` 的 `is null ? null :`，距我改的注释约 20 行）三次接触均不可见。

**失败链**（四环叠加）：
1. **目标污染** [推断]：片3 的 brief 是"谓词对照 + 三栈一致性（SQL 文本层）"；我的修改任务是"AOT 注释同步"。带着具体目标读文件时，注意力在目标象限内——`is null ? null : Serialize` 这个三元式**本身看起来无害**（有 null 处理！），只有与 PalORM 同位置对照才现形为分叉。
2. **对照层缺位** [实证]：ITM-807 谓词对照测试只对照 SQL 文本（正常路径），无"异常输入 → 行为"对照。PalORM 的 ITM-228 修复注释（PalOrmSagaStateStore.cs:205-214）就在片3 读过的文件里——没有任何检查项问"这个修复有没有姊妹同步"。
3. **声明受众分层未检查** [实证]：仓内文化"注释有声明即放行"（M3-3 保护机制），但 A-1 的声明只在代码 XML 注释（DapperServiceCollectionExtensions.cs:126-143），用户文档是"可选"口吻（usage.md:300）、README 零提及——**声明的受众分层**（开发者 vs 用户）不在任何检查词表。
4. **数据丢失类不在七流** [推断]：七流的"错误处理"检查异常纪律（吞异常/OCE 过滤），不检查"成功路径上的静默信息丢弃"。

### A-3 FanOut 整批重放（证据就在自己的测试里）

**接触史** [实证]：我自己写了表征测试锁定该行为——`PartialFailure_RetriesThenSucceeds` 断言 `ExecutedItems.Count == 3`（items=2，成功项执行 2 次），注释亲笔写"fan 整体重放"。

### T-1 CI 测试循环可空转

## 二、系统性根因（五条，按可机械化程度排序）

1. **跨栈行为对照无机械层**——SQL 文本有对照测试（ITM-807），"同契约方法 × 异常输入 × 三栈期望行为"没有对照矩阵。分叉只能靠运气（读的人恰好对比）。
2. **门禁/循环无空转守卫**——24 处 `find/EnumerateFiles` 循环型检查器中，仅 secret-scan 有"输入为空 fail-closed"（:65）；CI 测试循环与多数脚本无"扫描范围为空 → 红"守卫。
3. **证据新鲜度无门禁**——被引用的质量数字（覆盖率基线）无日期锚、无过期警示；"job 绿"与"数据新"混同。
4. **文档攻击面无扫描**——IP/拓扑/版本组合的泄露形态不在任何扫描器。
5. **视角集缺口**（最深层，已部分制度化）——L23/第八流把三个视角写入 prompt（概率层），但概率引导需要机械层兜底。

## 四、残余缺口（诚实声明，未机械化）

- **行为对照矩阵的完整版**（v2 M2-1，XL）：本轮已做两族——快照族（JsonTypeInfo 缺失，两栈）与 owner 守卫族（空白 owner，三栈，2026-09-19 二批增）；完整矩阵（每接口方法 × null/超界/租约被抢 × 三栈）待排期。
- **空转风险面实测收窄（勘正本报告初版的暗示面）**：二批对全部接线门禁做隔离空仓实测后确认——①`FindRepoRoot` 根锚定型（tech-debt/test-gate 等）与仓库共存亡，空仓"假绿"是探针 artifact（隔离仓里它们仍扫真仓，实测 [Test] 计数 1321 来自真仓库）；②ACMR 型中 encoding/secret/xml/vuln 均已 fail-closed（实测 rc≠0）；③真实风险面仅 CI 测试循环（M0-1 已修）与 cwd 目录枚举型（param-guard 已修）。初版"24 处循环仅 1 处有守卫"的表述夸大了暴露面——守卫缺失集中在两类已修形态，其余为设计内空集放行（doc-consistency 的 CI 无 .ai 声明）或语义正确跳过（ACMR 型无变更时跳过）。
- **Windows CI**（O-3）：需维护者决策（成本 vs 平台矩阵）。
- **brief 第二问的强制性**：第八流是 prompt 约束（概率层）——机械触发属过度工程，不做。
- **测量方法论教训**（本轮两次实证）：`cmd | tail; echo $?` 取的是 tail 的退出码——门禁退出码判定必须净化测法（`out=$(cmd); rc=$?`），本仓 AGENTS §3 管道掩码陷阱的变体，探针脚本编写时需注意。
