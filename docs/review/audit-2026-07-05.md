<details>
<summary><b>OBS-064 · HealthCheckExtensions catch 未过滤取消异常</b></summary>

**证据**：`src/PalDDD.Hosting.AspNetCore/AspNetCore/HealthCheckExtensions.cs:113-122`

```csharp
try
{
    await _store.GetPendingMessagesAsync(1, ...);
    return HealthCheckResult.Healthy("发件箱存储可用（DB 查询成功）");
}
catch (Exception ex)
{
    return HealthCheckResult.Unhealthy("发件箱存储不可用", ex);
}
```

`conventions.md` §10.3 要求 `catch (Exception)` 必须带 `when (ex is not OperationCanceledException)` 过滤。此处未过滤。

**论证**：健康检查的语义是"探测存储可用性"——取消异常（如应用关闭时）应返回 `Unhealthy` 还是传播？ASP.NET Core 健康检查框架通常期望返回结果而非抛出。这是设计权衡，非严格缺陷。但与成文规范不一致。

**建议**：若维持现状，在 `conventions.md` §10.3 增加例外说明"健康检查路径允许裸 catch"；若遵循规范，增加 `when (ex is not OperationCanceledException)` 过滤。

</details>

## 附：与用户规则的语义冲突说明

1. 用户规则针对「生产项目」——Pal.DDD 是 v1.0.0-preview.1 框架库，非生产应用。
2. ADR-005 已论证单目标理由：`OrderedDictionary<TKey,TValue>` 是 .NET 11 独占 BCL 类型，无 polyfill 轻量方案，是核心基础设施（消息目录的确定性枚举顺序）。
3. ADR-013 有完整的 Preview→RTM 迁移计划。
4. README FAQ 已明确说明"为什么要单目标 net11.0？"及已知限制。
5. ITM-060（开放项）将在 .NET 11 RC 发布后执行预验证。

**建议**：在 .NET 11 GA（预计 2026-11）后，执行 ITM-060 升级至 RTM SDK，届时与用户规则的语义冲突自然消解。
