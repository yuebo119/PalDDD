## 一、发现确认与论证（按严重性排序）

### 已确认成立（9 项）

**A-1｜MySQL 三栈租约互斥分叉——高**（亲证：三处 SQL 逐行对照）
- 证据链：EF 侧 `MySqlOutboxDbContext.cs:116-127` JOIN 派生表内 `FOR UPDATE SKIP LOCKED`（败者租他行）；Dapper 侧 `SqlTemplates.cs:127-131` 同 JOIN 形态无锁子句；PalORM 侧 `PalOrmOutboxStore.cs:126-135` 同 JOIN 无锁 + 两段声明自认（v13 取舍 + v43 双执行窗口补充）。
- 论证：同一物理表上两阵营互斥语义不同——无锁阵营在 (A写,A读,B写,B读) 交错时序下后写者覆盖先写者租约并回读到整批（**双执行**而非延迟）。**亲证新发现**：PalORM:129-130 给出 EF 侧未声明的取舍理由——JOIN 无锁是"避开 MySQL 派生表锁的版本兼容矩阵（8.0.18 以下行为差异）"，即 Dapper/PalORM 弃锁保旧版兼容、EF 弃兼容保互斥，**分叉是两侧有意取舍而非疏忽**。
- 后果推导：多实例 Dapper/PalORM MySQL 部署的重复投递率结构性高于 EF 部署；at-least-once 契约内由下游幂等兜底（消费方成本）。统一 = 推翻一侧取舍（需权衡兼容矩阵 vs 投递语义），故处置为 ADR 裁决而非直接修。
- 置信度：高（三处原文 + 双方声明互证）。

**D-1｜rc.1 预发布依赖锁定——高**（亲证：CPM 清单 + 抑制自认）
- 证据链：`Directory.Packages.props:5-15` 九包 11.0.0-rc.1.26425.128；`Directory.Build.props:42` NU5104 抑制明文"所有 PalDDD 包需随 .NET 11 GA 后统一升级并移除此抑制"。
- 论证：rc→GA 是日历确定的硬迁移窗口。rc 特有行为已有三例在案——ITM-261（EF SQLite preview 间翻译行为变更，`SqliteOutboxDbContext.cs:33-37` 注释）、`ExecuteSqlInterpolatedAsync` 过时（本会话实证）、BDN moniker 崩溃（`bench/Program.cs:12-16` 注释）——每例都是 GA 日的潜在回归点。
- 后果推导：无预案的 GA 日 = 35 包的被动全量回归 + 重发布；有预案 = 清单驱动的主动迁移。
- 置信度：高。

**O-1｜验证债：origin 落后 49 个提交——高**（亲证：git rev-list 计数，较审计稿的"16+"加重）
- 证据链：`git rev-list origin/dev..HEAD --count` = **49**（含本会话 16 + 维护者会话外批次）；CI 五 job（含 aot-verify 真发布运行）未在这 49 个提交的任何代码上运行过——其中含 Saga 骨架收敛（f5947f5）、EF SQLite 双下推（637e73d/24b6ede）、DapperAot 实验分支启用等 AOT 面实质改动。
- 论证：P0 #3 红线在仓内的表述是"IsAotCompatible=true + 0 警告 ≠ 运行时安全，声称兼容前必须有 PublishAot + 运行实测"——本地门禁链再全也没有 PublishAot 运行，这是该红线唯一指定的验证路径。49 提交积压使该验证的缺口随时间放大（冲突解决成本同向）。
- 置信度：高（git 事实）。

**A-2｜SQLite 时间列跨栈编码互不兼容——中**（亲证：spike 实验 + 源码）
- 证据链：Dapper 写入 `ToString("O")`（`DapperAotInitializer.cs:66`）；EF/PalORM 经 Microsoft.Data.Sqlite 原生参数写空格分隔格式；本会话主线程复现实验实证 `"O"` 参数对 provider 格式列的资格谓词**恒真**（错租，正确性级）。
