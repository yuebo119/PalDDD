<details>
<summary><b>OBS-066 · PostgreSqlAuditor SQL 字符串拼接（新发现）</b></summary>

**证据**：`src/PalDDD.Dapper.PostgreSql/PostgreSqlAuditor.cs:92-101`

```csharp
public static string AppendAuditLog(string tableName, string rowId, string operation,
    string? oldDataJson = null, string? newDataJson = null, string? changedBy = null)
{
    QuoteIdentifier(tableName, nameof(tableName));
    return $"""
    INSERT INTO audit_log (table_name, row_id, operation, old_data, new_data, changed_by)
    VALUES ('{EscapeLiteral(tableName)}', '{EscapeLiteral(rowId)}', '{EscapeLiteral(operation)}',
        {NullOrJson(oldDataJson)}, {NullOrJson(newDataJson)}, {NullOrText(changedBy)})
    """;
}
```

`EscapeLiteral` 实现（:147-148）：

```csharp
private static string EscapeLiteral(string s)
    => s.Contains('\'') ? s.Replace("'", "''") : s;
```

**论证**：
- `EscapeLiteral` 仅做单引号转义（`'` → `''`），在 PostgreSQL 默认配置（`standard_conforming_strings = on`，自 9.1 起默认）下安全。
- `QuoteIdentifier` 校验严格（字母/下划线开头，只含字母/数字/下划线），标识符路径安全。
- 但 `rowId`、`operation`、`oldDataJson`、`newDataJson`、`changedBy` 参数直接字符串拼接，非参数化查询。若调用方传入不可信输入且 PG 配置 `standard_conforming_strings = off`，存在理论注入风险。
- `Directory.Build.props:22` NoWarn CA2100 声明"所有 SQL 通过 SqlTemplates 常量 + Dapper 参数化"，此处不完全符合。
- 属工具类方法，调用方为框架内部/应用层，实际风险低。

**建议**：若维持现状，在 `PostgreSqlAuditor` 类注释增加"调用方应确保 rowId/operation 等参数来自可信源"说明；若遵循规范，将 `AppendAuditLog` 改为返回 `(string sql, object parameters)` 元组，由调用方通过 Dapper 参数化执行。

</details>

- 贡献者无法从源码修改元包依赖关系
