# ADR 022：分析器诊断与生成器诊断的分层关系 + 稳定名称谓词共享

> 状态：已采纳
> 日期：2026-09-10
> 关联：38 条编译期诊断审计（2026-09-10）、`src/PalDDD.Shared/StableNameValidation.cs`、ADR-014（分析器规则数稳定）

## 背景

对 38 条编译期诊断（15 条分析器 PDDD + 23 条生成器 PAL\*）做全量审计时发现两件事：

**一、三对诊断判定同一输入**

| 分析器 | 生成器 | 检查的值 |
|--------|--------|---------|
| PDDD009 | PALMSG004 | 消息名的稳定格式 |
| PDDD010 | PALMSG005 | 消息名的版本后缀匹配 |
| PDDD011 | PALMSG002 | `SchemaVersion >= 1` |

初判为"演化中意外形成的重复报告"，但实测证伪了该判断（见下）。

**二、`IsStableName` 谓词两处重复实现**

`PalDDD.Analyzers/StrategicDddAnalyzer.SymbolHelpers.cs` 与 `PalDDD.Core.SourceGen/MessageRegistryGenerator.cs` 各有一份逐字重复的私有 `IsStableName`（差异仅在于分析器版含 `IsNullOrWhiteSpace` 守卫，生成器版无）。两个包无共享代码机制，副本存在漂移风险。

## 决策

**决策一：维持三对诊断共存，不改判定范围、不删规则。** 它们是**分层设计**而非冗余。

**决策二：`IsStableName` 收敛为链接共享源码**（`src/PalDDD.Shared/StableNameValidation.cs`），两侧各编译一份内部类型，无程序集依赖。

## 理由

### 决策一：分层关系的实测证据

用探针项目同挂分析器 + 生成器，观测实际诊断输出：

| 场景 | PDDD009（分析器） | PALMSG004（生成器） |
|------|:------------------:|:-------------------:|
| 域事件 + 坏名 | ✅ 报 | ✅ 报 |
| **普通类** + 坏名 | ❌ 不报 | ✅ 报 |
| **泛型域事件** + 坏名 | ✅ 报 | ❌ 不报（生成器走 PALMSG006 提前返回） |

三条关键差异：

1. **覆盖范围不同**——分析器只覆盖领域事件（`DomainEvent` / `IDomainEvent`），生成器覆盖所有 `[GenerateMessage]` 类型。生成器的范围是分析器的超集。
2. **生成器跳过的路径由分析器兜底**——泛型声明下生成器提前返回（只报形态 PALMSG006），名称校验缺失，分析器 PDDD009 仍在守护。
3. **分析器可独立消费**——仅引用 `PalDDD.Analyzers`（不含生成器）时构建成功，PDDD009 仍生效；此时分析器是唯一名称守护。

严重级分工同样有意义：生成器侧全部 Error（阻断构建），分析器侧命名类为 Warning 且其中 PDDD010 配 CodeFix（`AddVersionSuffixCodeFix`）——**Error 阻断 + Warning 可一键修复**构成完整反馈链。

`git log` 与文档均无"诊断重叠"的设计讨论记录，说明这不是刻意的双保险设计，但结果上形成了合理的分层：分析器 = 领域事件语义层 + IDE 修复层；生成器 = 全消息类型层 + 构建门禁层。

### 决策二：共享谓词而非复制

选择链接共享源码（`<Compile Include="..\PalDDD.Shared\..." Link="..." />`）而非以下方案：

| 方案 | 不选原因 |
|------|---------|
| 提取为独立 NuGet 包 | 两个包都设 `SuppressDependenciesWhenPacking=true`（分析器包不携带依赖），新增包依赖会破坏该约束；且引入额外发布单元 |
| 生成器引用分析器程序集 | 两个分析器/生成器包必须相互独立（用户可各自单独引用），程序集依赖会迫使一起交付 |
| 放任两份副本 | 审计已证实现差分叉（空白守卫不一致），谓词约束必须在两侧一致 |

链接源码让两侧编译同一份文本（`internal` 类型，不进入公共 API 面），无运行时耦合，也无新增包。S3 反向验证：变异共享谓词后 `Core.Tests` 红 6 个、`Analyzers.Tests` 红 22 个——确认两侧实际消费该文件，非死代码。

## 影响

- 38 条诊断总数不变，判定行为不变（全量测试通过）。
- 新增 `src/PalDDD.Shared/` 目录（当前仅含此一个共享文件）；后续如需共享其他跨包谓词，沿用同一链接模式。
- 后人审计若再发现"重复诊断"，应先按本 ADR 的分层标准实测范围与兜底关系，再判定是否为真冗余。

## 不做

- 不删除 PDDD009/010/011（它们在分析器单独消费与生成器跳过路径上是唯一守护）。
- 不统一三对诊断的严重级（Error 阻断 + Warning 修复是分工，不是不一致）。
- 不将生成器的判定范围收窄到"仅领域事件"（生成器需覆盖所有 `[GenerateMessage]` 类型，包括非领域事件的消息）。
