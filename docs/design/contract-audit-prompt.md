# 框架库承诺审计提示词（v3，2026-10-22 依据 R9 实践修订）

> 适用对象：框架/库仓库的只读审计，判据是找出断掉的承诺并说清影响哪类消费者。
> 本版基于 2026-10-21 至 2026-10-22 在 Pal.DDD 的第 9 轮实跑（HEAD d792041，1851 用例基线，11 个探针，2 条 P2 缺陷 + 1 条 P3，随后完整修复并与量测两项性能候选）。
> 唯一可写目录：`/tmp/<audit>/`（含探针工程与复制镜像）。仓库只读，禁止 git 写操作、禁止修改仓库文件、禁止安装 SDK/工具/新包。允许 `dotnet restore` 拉取仓库已有依赖；包版本一律从 `Directory.Packages.props` 读取。

## 0. 工作循环

**承诺 → oracle → 变异或探针 → 同族扩散 → 成本模型**

0. **阶段 0 历史对账（新增，15 分钟内）**：先读 `.ai/perf-ledger.md`、最近三轮 `docs/review/*` 审计报告与 ADR 索引，列出 re-affirmed 清单（已裁决不做的项）。没有这一步，每轮都会重新提出同一批候选。
1. **收承诺**：文档、XML 注释、CHANGELOG、ADR、默认值、`[Obsolete]`、示例。每条写成"在什么配置下会发生什么"，可执行、可证伪。
2. **找 oracle**：现有测试、门禁、快照、分配断言、类型系统、CI job。
3. **有 oracle 就变异**，按 §1.6 的两种模式执行；无 oracle 就按文档最小路径写探针。
4. **同族扩散**：确认一条后，立刻查兄弟入口、其它栈、其它路径、其它默认值，并在台账写"家族边界"。
5. **成本模型**：对默认路径数单位成本（往返/分配/复杂度/并发），先过 5% 门槛与复活条件。
6. **只报能过四判据的**：其余进契约债务、边界模糊、判断项。

五条推论（保留）：
- 没有被 oracle 覆盖的承诺，就是风险面。
- 门禁通过不等于覆盖；变异是唯一证据。
- 静默错误比响亮失败更严重；默认配置下的静默错误最严重。
- 性能结论不需要墙钟，需要单位成本与保留的保证。
- 探针的产出不是表格行，而是"确认 / 推翻 / 更尖锐的下一个探针"。

## 1. 铁律

1. 发现格式：`编号 | 类型 | 声明 | 命令 | 首行输出 | 退出码 | 位置 | 证据强度 | 可达消费者`。
2. 命令自包含，以 `cd <仓库根> &&` 开头。探针命令允许追加 `cd <探针目录> &&`，并在台账标注探针工程绝对路径。
3. 不用 `| tail` / `| head` 作最后一段。必须取管道退出码时用 `set -o pipefail` 或 `${PIPESTATUS[0]}`；允许 head/tail 出现在中间段，但不得让它们吞掉退出码。
4. 缺失类结论必须给检索范围与排除项（obj/bin、历史目录、生成代码）。
5. 证据强度：E1 运行复现且有错误状态；E2 运行观察（符合/不符合文档）；E3 静态 + 现有测试/门禁；E4 仅阅读。E4 不得进缺陷清单，只有 E3 的 P0/P1 降到 P2。
6. **变异模式二选一，开工时声明（新增）**：
   - **隔离变异**：`cp -r` 源码（排除 bin/obj/.git）到 `/tmp/<audit>/mirror`，在镜像里改坏实现并跑测试。审计轮允许，产物只写 /tmp。
   - **只读替代**：不改任何源码，变异由仓库自带 `gate-audit` 等隔离探针承担。报告必须写"代码变异 0 条，替代证据 = gate-audit N 项 + 运行时探针 M 条"，并按 §9 把新增路径的无锁定测试直接列为 P1 候选（门禁假绿）。
   - 两种模式不得混用后仍声称"变异过"。
7. P0/P1 必须写反事实四格：哪个消费者 / 什么配置 / 做什么 / 看到什么。写不出就降级。
8. 禁止对未读文件做行为断言；行号以命令输出为准。
9. 性能四段对齐：承诺 → 接线 → 默认是否生效 → 证据。无量具时只给机制与单位成本，禁止墙钟数字。
10. 已被 ADR / CHANGELOG / 代码声明注释（P定案/勘正/取舍/登记延后/暂不优化）接受的项，标 re-affirmed 并引用原文；无新证据不计缺陷。
11. 空结果有效，但必须附探针台账：跑了什么、看到什么、为什么没成立。

## 2. 预算（90 分钟，到点砍）

| 阶段 | 内容 | 预算 | 检查点 |
|---|---|---|---|
| 0 | 历史对账与 re-affirmed 清单 | 10 | 第 10 分钟必须有清单 |
| 1 | 事实与承诺清单 | 10 | 第 20 分钟必须停止静态阅读 |
| 2 | 承诺-预言矩阵 + 假设 | 10 | 第 30 分钟必须有 10 条假设 |
| 3 | 探针与同族扩散 | 30 | 第 40 分钟必须跑出第一个运行时探针 |
| 4 | 性能成本走查与量测 | 15 | 第 70 分钟必须有门槛判定 |
| 5 | 核验与报告 | 15 | 第 85 分钟开始写报告 |
| 缓冲 | 返工 | 5 | |

**静态阅读硬上限 20 分钟（原始条目总和）**，超时立即转探针；R9 实测静态阅读 35 分钟，直接挤压了探针预算。

只做三件事的保底（顺序不变）：
1) 注册入口独立装配、能力接口 × 实现者、告警/指标 × 路径覆盖；
2) 每条核心承诺找 oracle，按 §1.6 至少变异 2 个；
3) 三条主流程的每消息成本走查。

砍单顺序：性能深化 → AOT 发布 → 文档示例 → 门禁变异。

## 3. 阶段 1：事实与承诺

### 3.1 脚本化事实

```bash
cd <repo> && git log --oneline -3 && git status --porcelain
find src -name '*.cs' -not -path '*/obj/*' -not -path '*/bin/*' | wc -l
find src -name '*.csproj' | wc -l
grep -rn -a 'async void' src --include='*.cs' | grep -v '//' | wc -l
grep -rn -a -E '\.Result\b|\.Wait\(\)|GetAwaiter\(\)\.GetResult\(\)' src --include='*.cs' | wc -l
grep -rn -a -E 'DateTime(Offset)?\.(Now|UtcNow)|Guid\.NewGuid' src --include='*.cs' | wc -l
grep -rn -a -E 'MakeGenericType|Activator\.CreateInstance|Assembly\.GetTypes|Type\.GetType\(' src --include='*.cs' | wc -l
dotnet build <sln> -v q        # 记录"0 个警告 / 0 个错误"两行
dotnet test <sln> -v q         # 总计/失败/成功/跳过
```

ugrep 环境修正（R9 实测）：
- `grep -E '^\+.*'` 对 diff 头 `+++` 会报 `invalid syntax`。排除头用 `grep -a -v -F '+++'`，或直接 `git diff --stat`。
- `grep -rl` 可能输出 Windows 反斜杠路径，循环里再交给 grep 会 "No such file"。统一走 `find ... | xargs grep ...`。
- 日志含 GBK 时用 `grep -a`，断言只匹配 ASCII 测试名或 EventId。

既有防线全部跑一遍，并记录盲区：accepted-gap、CiOnly、跳过项、只调用不断言的格子。
与历史基线偏差 >10% 的，标注是口径差异还是真变化。

### 3.2 增量面

显式选基线：`git describe --tags --abbrev=0 --match 'v*'`；不可达时取 main 上最近 tag 并写明理由（R9 实测：dev 上 describe 返回旧 tag v3.1.0，实际基线应为 v4.0.0）。

```bash
git diff <base>..HEAD --stat -- src
git diff <base>..HEAD -- src | grep -a -E '^\+' | grep -a -v -F '+++' | grep -a -E '\b(public|protected internal)\b'
```

### 3.3 承诺清单（≥15 条）

抽取含数字、默认、上下界、"自动/所有/全部/始终/保证/必须"的句子。
每条：`承诺原文 | 出处 file:line | 最小验证路径 | 现有 oracle`。
优先：默认值、阈值、支持矩阵、告警覆盖范围、升级步骤、示例可运行性。

产出 `facts.md`、`promises.md`。末尾一行"阶段 1 完成/未完成"。

## 4. 阶段 2：矩阵与假设

### 4.1 矩阵

`承诺 | oracle | oracle 能红吗（变异结果） | 探针 | 观察 | 结论`
- oracle 填具体测试名/门禁名/断言；没有就写"无"。
- 标"无"或"红不了"的行，就是本轮主攻方向。
- 变异列必须写模式（隔离变异 / 只读替代），不得留空。

### 4.2 假设（10 条）

`H<n> | 承诺/接缝 | 会在哪个配置或调用下失败 | 探针步骤 | 判据（看到 X 成立 / 看到 Y 推翻）`
硬性要求：
- ≥6 条必须运行时才能判；≥2 条针对增量面；≥1 条是"门禁假绿"。
- 每条必须可证伪。

产出 `matrix.md`。末尾一行"阶段 2 完成/未完成"。

## 5. 阶段 3：探针与同族扩散

探针是种子，每个 ≤5 分钟，超时记 blocked 换下一个。
合法产出只有三种：confirmed（附证据）/ refuted（附观察到的正确行为）/ next（更尖锐的假设）。

### 5.1 种子（4 个运行时 + 2 个静态矩阵）

| # | 种子 | 装配要点 | 成立条件 |
|---|---|---|---|
| 1 | 注册入口独立装配 | 只调 `AddLogging()` + 一个公开 `Add*` + 文档声明的最小依赖，解析全部 `IHostedService` 与 scoped processor | 文档路径启动/首用抛异常，或错误不点名缺失类型 |
| 2 | 能力接口 × 实现者 | 枚举能力接口 × 实现；看未实现时的回落分支、日志、指标 | 文档承诺优化但回落无信号，或信号只在 Debug |
| 3 | 告警/指标 × 路径 | 每个 EventId/计数器 grep 全部调用点，画 单条/批量、成功/失败/取消 覆盖表 | 无限定承诺"处理器会记录…"在某路径缺失 |
| 4 | 组件交互 | 至少 4 组：Auto 投递 × 无立即写 store；raw 发布 × 追踪头；批量 handler × 检查点；批量 Inbox × 无能力 store | 头部丢失、静默降级、重复终态、错误状态 |
| 5 | 默认值三方对账（静态） | 属性默认 vs 解析逻辑的有效值 vs 文档数字 | 三者任一不一致且影响行为 |
| 6 | 旧数据首轮（静态或探针） | NULL 到期、Failed 检查点、旧编码、旧版本行，跑新默认路径 | "自动兼容/首扫回填"不成立 |

### 5.2 探针工程骨架（R9 实测，复制即用）

最小控制台工程：`net11.0`、`ManagePackageVersionsCentrally=false`、`ProjectReference` 指向目标项目。必带四件补偿器：
1. `IPalLogger<T>` 捕获实现：必须**显式覆盖结构化重载** `(EventId, string, params object?[])`，否则默认实现会把 EventId 吞成 0；模板参数是 `{Name}` 具名占位符，不能用 `string.Format` 渲染。
2. `IOptionsMonitor<T>` 固定值实现（CurrentValue/Get/OnChange）。
3. store 包装器：转发全部方法，按需抛异常或返回部分命中。
4. 手动 `TimeProvider`（需要推进时钟时）。

```csharp
sealed class CapturingLogger<T> : IPalLogger<T>
{
    public List<(int EventId, string Message)> Rows { get; } = [];
    public void Debug(string m) => Rows.Add((0, m));
    public void Information(string m) => Rows.Add((0, m));
    public void Warning(string m) => Rows.Add((0, m));
    public void Error(Exception e, string m) => Rows.Add((0, m));
    public bool IsEnabled(LogLevel level) => true;
    public void Debug(EventId id, string m, params object?[] a) => Rows.Add((id.Id, m));
    public void Information(EventId id, string m, params object?[] a) => Rows.Add((id.Id, m));
    public void Warning(EventId id, string m, params object?[] a) => Rows.Add((id.Id, m));
    public void Error(Exception e, EventId id, string m, params object?[] a) => Rows.Add((id.Id, m));
}
```

运行：`dotnet build -v q` 后直接跑 exe（R9 实测测试宿主与探针工程均可用；MTP 项目用 exe 跑比 `dotnet test <单项目>` 稳）。

### 5.3 同族扩散（至少 3 个方向）

入口族、路径族、栈族、默认族、数据族。每确认一条，在台账写一行"家族边界"：查过哪些兄弟、哪些未查、为什么。

## 6. 阶段 4：性能机会

### 6.1 每消息成本走查（三条主流程）

命令分发、Outbox 发布、Inbox 消费（有流式则加一条）。
`步骤 | 位置 | 单位成本 | 证据 | 可收敛点`

### 6.2 只接受五类主张

往返收敛、分配消除、复杂度、并发/流水线、缓存/预计算。

### 6.3 每条必须写全（新增两个字段）

- 触发条件（默认 or opt-in，哪个栈）
- **保留的保证**（fencing/顺序/at-least-once/幂等/AOT/零反射，违反任一即禁止提出）
- 测量路径（现有 bench lane / smoke 断言 / 计数器 / 无本会话量具）
- 回退开关
- **判定门槛**：默认「收益 <5% 不做」；必须给百分比与分母口径
- **复活条件**：什么可观测信号出现时复议

### 6.4 量测预算（≤15 分钟）

- 用 `/tmp` 微探针，Release 构建，同进程 A/B 交替 7 轮取中位数。
- 必测空委托噪声地板；计时只作趋势，分配可作判定。
- 需要真实 broker/真库而本机不具备时，写明"占比只会更小"的方向判断，不猜测数值。
- 否决结论写入 `.ai/perf-ledger.md` 的表 2（明确不做），格式：项 | 理由（含门槛判定与语义成本） | 数据（含噪声地板与分母）。

产出 `perf.md`（≤8 条，按 收益×可达×确定性/成本 排序）。末尾"阶段 4 完成/未完成"。

## 7. 阶段 5：核验与报告

1. 逐条重跑阶段 3/4 的命令；退出码非 0 或输出为空整行丢弃，写 `discarded.tsv`。
2. 依赖前序状态的改写为自包含；改不了即丢弃，禁止修补失败行。
3. 通过的行写 `verified.tsv`。
4. 每条 P0/P1 再答一次反事实四格；答不出即降 P2 或移出。
5. 按 §10 写七章报告。

## 8. 缺陷分类速查

| 类型 | 触发 | 成立条件 |
|---|---|---|
| 注册/装配 | 每个公开 `Add*` 单独装配并解析 | 文档路径启动或首用失败 |
| 默认值漂移 | 属性/解析/文档三方对账 | 不一致且影响行为 |
| 能力回落 | 能力接口 × 实现者 | 承诺优化但回落无信号 |
| 跨栈/方言分叉 | 同输入跑多栈多方言 | 空/零/重复/失败/时间语义不同 |
| 文档失实 | 承诺清单逐条执行 | 命令结果与声明不符 |
| 错误不可行动 | 四类误配 | 不点名键、不给下一步 |
| 生命周期 | 启动/停止/取消/释放 | 丢消息、状态错、资源泄漏 |
| 并发一致性 | 过期重租/双实例/长 handler/部分失败 | 旧 token 生效、重复终态、整批中止 |
| 新面未接线 | 新 API/告警/选项 × 全部调用点 | 只覆盖部分路径 |
| 测试/门禁假绿 | 变异坏输入 + 空输入 | 仍绿，或只调用不断言 |
| AOT/裁剪 | publish + run | 运行期失败 |
| 性能机制 | 成本走查 | 有路径与单位成本，且不破坏保证 |

每条发现必须能回答：哪个消费者、什么配置、做什么、看到什么。

## 9. 严重度

先定两个轴：可达面（全部消费者 / 单栈 / 单方言 / 仅自定义实现 / 仅 AOT）、可检测性（响亮 / 可观测 / 静默）。

| 级别 | 判据 |
|---|---|
| P0 | 默认配置 + 全消费者 + 静默错语义或数据风险；安全；AOT 发布失败 |
| P1 | 文档路径启动/首用失败；文档保证的**行为**静默缺失；升级后旧数据首轮错误；门禁在坏输入下不红 |
| P2 | 契约/文档漂移、可观测性缺失、未测边界、性能机会（无本会话量具）、能力回落无信号 |
| P3 | 不报，最多一行进附录 |

**可观测性定级锚点（新增，R9 实践）**：
- 告警 EventId 缺失、指标与 DB 真相不一致、成功/失败信号互相矛盾，但消息仍可重投、数据不丢：P2。
- 只有当"缺失的信号本身被文档承诺为唯一出口"（例如运维按该 EventId 做数据修复），才升 P1。
- 纯日志文本差异、无 EventId 的 Warning：P3。

排序：`严重度 × 可达面 × 可检测性 / 修复成本`。超过 8 条先做同族合并，再自检是否凑数。

## 10. 输出模板（七章，不增不减）

1. **运行事实**：HEAD/工作树、build/test 与跳过构成（按外部依赖类别汇总，MTP 无逐项目汇总）、既有防线与盲区、所选基线、变异模式、探针完成 X/N、discarded、耗时、静态阅读实际时长。
2. **结论摘要**（≤10 行）：Top 3；一句话边界声明（保证什么 / 明确不保证什么）。
3. **缺陷清单**（≤12，按严重度）：声明、触发、证据（命令/退出码/首行）、反事实四格、修复方向、**锁定测试（名称 + 修复前应红的断言）**、可达消费者。
4. **承诺与边界债务**：矩阵摘要（多少条有 oracle、多少条变异能红）、能力矩阵、边界模糊项。
5. **性能机会**：五类表（机制/位置/单位成本/保留保证/测量路径/判定门槛/复活条件/强度），标"无本会话量具"。
6. **探针台账**：每个探针的 confirmed/refuted/blocked + 原始输出 + 家族边界。
7. **未完成与不确定**：discarded、blocked、降级、re-affirmed（引原文）、什么会改变结论。

## 11. 本仓适配（换仓时替换本节）

最小消费方：`/tmp/<audit>/<probe>/`，net11.0，ProjectReference 指向 src 目标项目；必加包版本取自 `Directory.Packages.props`。
SQLite 建表用 `docs/sql/sqlite/000_schema.sql`。

已知坑（R9 实测补充）：
- dev 分支 `git describe` 可能解析到旧 tag，基线显式取 `git tag --sort=-v:refname` 首个可达版本。
- `grep -rl` 在 ugrep 下返回反斜杠路径，循环会失败；用 `find | xargs grep`。
- diff 头排除用 `grep -a -v -F '+++'`，不要用 `\+\+\+` 正则。
- 测试输出可能 GBK：`grep -a` + ASCII 名称。
- 不要用 heredoc / `sed -i` 写文件（守卫会拦）；用 Write/Edit，临时工程放 /tmp。
- 审计只写 /tmp，避免触发行尾/BOM 门禁；`Write` 新建文件默认 LF，新文件在仓库内须转 CRLF。
- `nupkgs/` 可能是旧版本产物，不要引用。
- EF InMemory 的 `Dispose()` 等价 `Close()`，别用它造"断连"探针。
- 全绿口径必须披露跳过数与排除面；MTP 用测试 exe 直跑比 `dotnet test <单项目>` 稳。
- 审计结论需要落地修复时，审计与修复分两轮：审计轮只读；修复轮按仓库提交纪律走（锁定测试先红后绿、门禁、同提交文档同步）。

## 12. 反模式

1. 只做静态盘点就宣称"未发现问题"。
2. 用"测试全绿"当覆盖证据，不做变异。
3. 只有 grep 证据的 P0/P1。
4. 探针只填表，不产生 confirmed/refuted/next。
5. 无调用路径的性能建议；无量具的墙钟数字。
6. 建议违反 AOT 与零反射红线。
7. 对未读文件做行为断言，或把注释当运行行为。
8. 重复上报已接受项；把 accepted-gap 当新缺陷。
9. 用"需前提"软化反事实。
10. 用"建议进一步深入分析"收尾。
11. **声称变异过但实际没改任何实现**（新增，按 §1.6 声明模式）。
12. **把"信号缺失"直接定 P1 而不查数据是否仍可恢复**（新增，按 §9 锚点）。
13. **性能候选不给分母与噪声地板就报百分比**（新增）。
